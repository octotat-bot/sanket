# Sanket

Real-time Indian Sign Language (ISL) **word** recognition that runs entirely in your browser:
sign a word to your webcam and see it recognised. No video leaves your device.

Live demo: not deployed yet.

This is isolated word recognition for a vocabulary of 50 words (INCLUDE-50). It is not a
sign-language translator and not a replacement for interpreters. ISL is a complete language with
its own grammar; this covers a tiny part of it.

## How it works

```
webcam → downscale to 480 rows → MediaPipe Holistic → keypoints → sign spotter → features → model → word, or "not sure"
```

- **Downscale and MediaPipe**: the same 480-row resize and the same MediaPipe model bytes (pinned by
  sha256) as offline extraction, so the keypoints the model sees live match the ones it was trained on.
- **Sign spotter**: decides when a sign starts and ends from raised, moving hands.
- **Features**: shoulder-normalised body and hand-local coordinates, resampled to 64 frames. The same
  code exists in Python (training) and TypeScript (browser), checked against shared golden files.
- **Model**: ONNX in a Web Worker, on WebGPU when available, otherwise WebAssembly.

## Key decisions

- Keypoints, not pixels, and the same extractor in training and in the browser:
  [ADR 001](docs/decisions/001-same-extractor-pinned-by-hash.md),
  [ADR 002](docs/decisions/002-holistic-vs-hand-plus-pose.md) (Holistic vs Hand + Pose),
  [ADR 007](docs/decisions/007-offline-extraction-resolution.md) (480 rows everywhere).
- Features: [ADR 008](docs/decisions/008-features-v1.md).
- Sign spotting, rejection ("not sure"), quantisation and the browser runtime:
  [ADR 009](docs/decisions/009-live-spotting-rejection-runtime.md).
- Evaluation without leakage (validation is carved from train, never test):
  [ADR 003](docs/decisions/003-dataset-source-of-truth.md),
  [ADR 005](docs/decisions/005-session-independent-evaluation.md).
- Privacy enforced by the browser: the page may only contact its own origin
  ([ADR 006](docs/decisions/006-block-third-party-requests.md)).

## Limitations

- Isolated words only, 50 of them. No sentences, no fingerspelling.
- INCLUDE was recorded in controlled conditions. Expect lower accuracy on everyday webcams, with
  seated users, other backgrounds and other lighting.
- INCLUDE has no signer ids, so the official test number can't show how well the model handles
  people it has never seen. Session-independent evaluation (ADR 005) is future work.
- The planned real-webcam test set is small: the author and two friends, **non-native signers
  imitating INCLUDE references**. It shows how the app works for people like them, not for fluent
  Deaf signers.
- Spotting and rejection thresholds are hand-set (ADR 009).

## Run locally

Requires [uv](https://docs.astral.sh/uv/), Node 22 and pnpm 12.

```bash
make setup     # pinned Python and web environments
make models    # pinned MediaPipe models (sha256-checked)
make ci        # lint, types, tests, MediaPipe smoke tests, production build
cd web && pnpm build && pnpm start   # then open http://localhost:3000
```

## Reproduce training

1. `make extract-include50` downloads only the 958 INCLUDE-50 videos (HTTP range requests to
   Zenodo) and extracts keypoints. No videos are kept.
2. `make upload KAGGLE_DATASET=<you>/<slug> ONLY=include50` uploads the keypoints as a private
   Kaggle dataset.
3. Run [`ml/notebooks/kaggle_include50.ipynb`](ml/notebooks/kaggle_include50.ipynb) on a T4 GPU. It
   trains the GRU baseline and the Transformer from `ml/configs/*.yaml` (seed 0) at a pinned commit.
4. `make collect-run RUN=…`, `make export-onnx CONFIG=… RUN=…`, then `make report`.
