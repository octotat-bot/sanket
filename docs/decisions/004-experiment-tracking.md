# ADR 004: Experiment tracking with TensorBoard

- Status: **Proposed** (needed from Phase 2. Approve or switch to MLflow.)
- Date: 2026-11-24

## Context

CLAUDE.md allows TensorBoard or local MLflow, and asks us to pick one. Training runs on Kaggle
(12 h sessions, outputs downloaded afterwards) and sometimes locally. Results that go in the
README come from `make report`, not from the tracker. The tracker is for watching and
comparing runs.

## Options

- **TensorBoard**: event files written next to each checkpoint and viewable straight from
  Kaggle output folders. No server or database. Metric scalars and curves only. Hyperparameter
  comparison is basic.
- **MLflow (local file store)**: better run comparison, parameter tables, and artifact
  tracking. But it means a local server and a directory store to sync between Kaggle and the
  laptop. It is also a heavier dependency.

## Decision (proposed)

TensorBoard. Each run's config YAML plus git SHA is saved beside its event files. That covers
reproducibility. The ablation table is generated by our own script from saved metrics JSON,
not from the tracker.

## Tradeoff

Comparing many runs side by side is clumsier than in MLflow. With fewer than about 20
ablation runs, that is acceptable.
