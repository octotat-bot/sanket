# ADR 003: Dataset source of truth and split handling

- Status: Accepted (Phase 0, approved by Mukund 2026-11-24)
- Date: 2026-11-24

## Context

All numbers are in `reports/phase0_inventory.md`, generated by `make inventory`.

- Videos: Zenodo record 4010759, 44 zips, 56.75 GB, md5 per zip published by Zenodo.
- The split link on Zenodo (Google Drive) returns **404**. `Train_Test_Split.zip`, which the
  record's own `download_data.sh` fetches, is **not in the record**.
- The authors' code repo (AI4Bharat/INCLUDE, MIT) has `train_test_paths/*.txt` and the label
  maps. `train + val` matches the counts Zenodo states (INCLUDE 3475 / 817,
  INCLUDE-50 766 / 192).
- 605 split entries say `.MOV` where the zip holds `.MP4`.
- The class **"Second (Number)"** (8 videos: 6 train, 1 val, 1 test) is in the splits and the
  263-class label map, but its videos are in no zip. Zips cover **262** classes, 4,284 videos.
- The INCLUDE-50 and INCLUDE splits are **not nested**. 146 INCLUDE-50 training videos are
  INCLUDE **test** videos, and 159 INCLUDE-50 test videos are INCLUDE training videos.

## Decision

1. Videos come from Zenodo, verified by Zenodo's md5. Split files and label maps are vendored
   unmodified from AI4Bharat/INCLUDE@`df348f4` into `ml/data/splits/`, with sha256 pinned by a test.
2. Videos are matched to split entries by `video_key` (lower-cased path without extension).
   File names alone are not unique: 508 `MVI_####` stems repeat across folders.
3. Labels are derived the way the authors' code does it (letters of the class folder,
   lower-cased), and every split label must exist in the label map (tested).
4. Full INCLUDE is evaluated on the **816** test videos that exist. The report states this,
   and the class "secondnumber" is reported as untrainable. The paper's 85.6% is quoted with
   that caveat.
5. **INCLUDE-50 and INCLUDE experiments never share weights.** A model trained on INCLUDE-50
   train must not be fine-tuned and then evaluated on INCLUDE test, because that leaks 146
   test videos. "Scaling to 263 classes" in Phase 3 therefore trains from scratch on INCLUDE
   train (or from a checkpoint trained only on INCLUDE train).
6. Validation for early stopping and tuning uses the authors' `val` files, which are carved from
   train. The test split is used only for final numbers.
7. **Hyperparameters for full INCLUDE are tuned only on a validation split carved from INCLUDE
   train** (the authors' `include_val.txt`). Settings chosen on INCLUDE-50 are a starting
   point at most. Each one must be re-validated on INCLUDE val before the full-INCLUDE test run,
   because INCLUDE-50's train/val overlap INCLUDE test (146 videos) and choices tuned there
   could carry test information over. Each experiment config records which split its
   hyperparameters were selected on.
8. **Reporting.** Full-INCLUDE results are always labelled "262 of 263 classes, 816 of 817 test
   videos". Wherever the paper's 85.6% (263 classes, 817 test videos) is shown next to ours, a
   note says the class `secondnumber` has no videos on Zenodo, so the numbers are close but not
   strictly comparable. The missing test video is never counted as correct or wrong. It is
   excluded and the exclusion is stated.

## Tradeoff

We depend on a GitHub repo for splits instead of the dataset record. Vendoring with pinned
hashes and recorded provenance makes that safe and reviewable. Using 816 / 262 instead of
817 / 263 makes our full-INCLUDE number not strictly comparable with the paper's. We say so
instead of hiding it.

| Source | What it says |

| Hugging Face `ai4bharat/INCLUDE` dataset card (official, by the authors) | `license: cc-by-4.0`, and nothing contradicting it in the card text. The card adds an ethics request: respect the privacy and dignity of the signers |
| GitHub `AI4Bharat/INCLUDE` | MIT, but that file covers the **code** and says nothing about the dataset |
| IEEE DataPort "Silent Voice: MediaPipe Holistic landmark tensors…" (a *derived* dataset by a third party) | says INCLUDE is CC BY-NC-SA 4.0 and licenses its derivative that way |

Decision (Mukund): credit INCLUDE as **CC BY 4.0**, following the primary sources. The one
disagreeing source is a third-party derivative. We do not use that derivative, and the project
stays non-commercial anyway. The HF card's ethics request is why raw dataset frames are never
committed, published, or shown in the app (spot-check frames stay in the local cache).
